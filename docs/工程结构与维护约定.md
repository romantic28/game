# 工程结构与维护约定

本文件描述当前工程的实际组织。项目名称待定，界面统一使用“染色玩法开发预览”。2026-10-27 整理，当前暂停功能阶段推进。

## 模块职责

`src/Main.ts` 是 Laya 场景入口。它只管理启动、异常提示和销毁；场景脚本路径与 UUID 保持稳定。

`src/app/MountParty.ts` 负责把棋盘挂到舞台、注册／注销尺寸监听；`Layout.ts` 计算竖屏缩放与居中，不持有玩法状态。

`src/gameplay/types.ts` 定义颜色、棋盘、关卡；`Rules.ts` 管理原同色区域、步数、撤销、重来、胜负和忙状态；`SampleLevels.ts` 保存三个验证样板，后续正式关卡不继续塞进规则类。此模块不依赖 Laya、角色或绘制实现。

`src/board/PartyView.ts` 组装检查界面、处理输入、持有棋盘格与共享动画循环，协调规则与角色；`GridAppearance.ts` 提供纯格子遮罩和外观。PartyView目前仍包含界面和动画协调两项职责，未来如需拆分，需先明确取消／重建时的生命周期，不能仅按代码行数拆类。本轮不改动这些行为。

`src/effects/Wave.ts` 只在冻结的 changed 集合中安排距离与时序，记录前驱格并按共享边中点到达时刻交接；染色波最多1800ms，超出时统一缩放全部染色时序。`DyeFront.ts` 提供与现有GPU阈值对应的归一化到达计算，`PaintFront.ts` 复用它生成遮罩后端和纯格子的波前几何；参数需与CharacterGpuArt中的GLSL同步维护。它们不判定染色集合。

`src/characters/CharacterResources.ts` 管理物种路径、预加载和共享表情装配；`CharacterGpuArt.ts` 是单纹理四色图集的 GPU 后端；`CharacterStaticArt.ts` 是原遮罩对照后端；`CharacterMotion.ts` 管理身体、投影和表情的动作状态。两个后端均依赖共享资源装配，不互相依赖。Static 是历史文件名，当前并不表示只能静态显示。

## 依赖与改动边界

入口通过 app 挂载 board；board 协调 gameplay、effects、characters。gameplay 不反向依赖表现层。资源加载与共享表情不应移回某一个绘制后端，避免 GPU 为了加载资源而引入遮罩实现。

染色对象始终为操作前原同色共边区域 changed；原目标色邻队回应仅使用 team 减 changed。五官、物种、动作和绘制模式不改变规则。保持固定格位与命中区域；重来、切样板和销毁需要清除动作与表情状态。

新增源码放入对应职责目录；跨模块用明确相对导入，不建立通用杂物目录。类、接口与导出符号沿用 PascalCase；函数、变量沿用 camelCase。使用四空格缩进，代码保持可读换行；注释说明引擎约束、范围和生命周期原因。新增参数先归属实际模块，不为少量常量创建全局配置中心。

移动 Laya 脚本时连同 `.meta` 移动，保留 UUID；新脚本需有唯一 `.meta`。不能仅修 TypeScript 导入而遗漏场景引用。`Main.ts` 本次留在根目录，Scene UUID 和组件 UUID 均未变。

## 资源、生成物与归档

`assets/characters/` 内 horn-restart-v2、cyclops-v2、rabbit-v2 是当前资源标识，保留导入元数据，不为目录美观重生成 UUID。每种角色同一256画布，四色身体／格底分开，五官保色。GPU图集由外层工具生成，禁止手修生成图集；美术源保存在外层 art。

`library/`、`local/` 是 IDE 管理的数据；`bin/` 是 IDE 预览区，`bin/index.html` 为需保留的模板；`browser/` 为独立构建。engine 声明、settings 配置、templateInfo 模板信息各自保留，不混入业务源码。

`.gitignore` 阻止继续新增缓存和生成物；历史已跟踪缓存仍在索引中，本轮没有强制移除、覆盖或清空。后续决定仓库提交策略时可单独审查，不以忽略规则宣称 Git 已完全干净。

未引用的 HornStaticArt、MonsterPlaceholder 及旧测试输出移至外层 archive/DEV-0072-project-organization，保留源码、meta和整理前快照。历史文档中的旧路径仅作当时记录，新开发以本文件和README为准。

## 路径规范

源码、场景、资源清单和共享配置使用相对路径或资源UUID；不写入用户盘符、安装目录、home路径。外部软件位置用用户环境变量LAYA_RESOURCES／PHOTOCRAFT_CLI或PATH配置，外层toolchain统一解析。SDK是项目内忽略的本地依赖。引擎声明中的路径示例、第三方库和IDE缓存不属于手写路径配置，不批量替换。新增手写路径可用外层node tools/check-portable-paths.cjs检查。

## 静态检查与运行验证

编辑器TypeScript应与当前Laya工具链4.9.5保持一致。`.vscode/settings.json` 的SDK键仅使用项目相对路径node_modules/typescript/lib；本机配置LAYA_RESOURCES后，从外层执行node tools/setup-editor-sdk.cjs复制匹配SDK，node_modules被ignore，换机重新准备；打开TS文件后执行 `TypeScript: Select TypeScript Version` → `Use Workspace Version` 才会切换。TS6的node／node10弃用提示不等于4.9.5配置错误，不直接向Laya配置加入ignoreDeprecations6.0或改用新版本专有解析模式。

在外层执行 `node tools/check-project-structure.cjs` 检查 TS 语法、导入路径与环依赖、脚本 UUID、场景入口和验证脚本路径，不执行游戏或类型检查。`node tools/build.cjs` 生成独立网页；`node tools/check-character-static.cjs` 检查资源尺寸、哈希及副本。

游戏测试脚本与真实播放遵循用户当前验收分工，不自动运行。IDE 重新导入后的编译、实际点击／染色、撤销／重来、表情恢复、GPU渲染及手机性能由运行验证确认，静态检查不能替代。
