# 角色定义与素材接入

2026-10-27。此次整理保持三个现有角色、染色规则及动作时序；不代表动态验收或V0.2收尾。

## 唯一配置入口

`src/characters/CharacterDefinitions.ts` 是无引擎依赖的数据定义：角色键即稳定ID，Species从键推导。名称、资源目录、完整画布、脚底／投影锚点、图层及其父容器、固定部件、calm／happy表情和回弹参数在此维护。运行装配和外层工具均读取它；不要在其他模块重新增加物种分支。

外层 `tools/character-definitions.cjs` 用配套TypeScript转译并读取此可信数据文件，不启动游戏。该文件应保持纯数据，不导入游戏模块或执行外部代码。

## 本轮支持的素材协议

- 四色顺序R、Y、B、G；每层完整256×256画布，GPU四色图集1024×256。定义中的canvas用于锚点换算和校验，不代表渲染器已支持任意尺寸。
- 图层槽位依次为tile、shadow、body、fixed。tile和shadow属于固定格位；body、fixed及表情属于actor。当前检查器明确拒绝其他拓扑；新增遮挡结构或独立肢体需要适配后端，不能仅改配置。
- 可染层为tile和body；投影独立；fixed只包含两种表情都显示的部件，不能重复列入眼嘴等表情替换部件。表情内部数组顺序为绘制顺序。
- 所有PNG已经在同一画布中配准，锚点只控制整体动作，不再次应用制作阶段的位移。兔耳内外仍在body，小角怪双角仍保色。
- 基础动作仍为整体回弹与合群回应；新增小角怪可选两姿势切换，未增加通用动画系统。独眼头顶留白有限，保持其小抬升参数。

## 制作与运行分开

制作源和导出源保存在外层art；源目录与个别表情文件映射在外层 `tools/character-sources.json`，以角色ID关联定义。源路径不打进运行配置，路径相对外层工作区。

运行PNG和meta放在game/assets/characters；manifest.json由工具生成，只记录角色ID、画布、固定部件、文件哈希及图集信息。不要手工维护第二份部件清单，不把清单中的描述当成验收状态。新文件生成meta，已有meta保持UUID。

## 新增符合协议的角色

1. 准备同画布、同源、已配准净边的四色body／tile、shadow、固定部件和两状态表情。
2. 在CharacterDefinitions添加ID与定义，在外层character-sources.json添加制作输入映射。
3. 配置LAYA_RESOURCES后，从外层运行check-character-definitions.cjs，再运行prepare-character-static.cjs。后者先校验全部定义与源尺寸，再打包所有角色并生成GPU图集。
4. 按需build.cjs及check-character-static.cjs检查运行资源和网页副本。两者均由定义取得角色范围。
5. 由用户在IDE和实际播放中确认配准、净边、遮挡、四色、表情及动作。静态检查不能证明视觉配准或动态表现正确。

检查界面角色名来自定义，少量增加角色时按钮宽度自动适配；大量角色需要后续分页选择，当前不做大型素材浏览器。

## 加载与关卡边界

loadStaticArt和staticArtReady支持指定Species集合，默认仍为全部角色，以保留现有混排和单物种切换。此轮未增加按关卡自动选择、GPU／遮罩分别加载、远程下载或资源释放；不要误称已实现完整按关卡资源管理。

SampleLevels仅为规则／表现检查样板，现有样板增加稳定sample-* ID。Level的id暂为可选以兼容旧验证输入；未来正式关卡入口应要求ID唯一且必填，并将展示顺序与ID分开。角色排布与背景不进入Rules；本轮未制作正式关卡库或进度系统。

## 一致性与备份补充

素材变更后显式运行外层prepare-character-static；build会先比较声明的制作输入与运行PNG、解码图集像素并检查残留，过期时停止构建，不自动刷新图集。runtime-only检查不依赖browser。检查PNG来源不等于检查pcraft已重新导出。工具不删除残留或重生成已有meta。

完整恢复需要外层art／tools／docs及game未提交内容和Git历史；仅提交game不能备份整个制作工程。外层docs/完整备份与恢复约定.md和美术资源一致性与残留检查.md说明快照、异地保存及手工处理边界。

## 小角怪姿势样板补充（2026-10-27）

定义支持可选poses.raisedBody（当前仅raised-body），外层源映射使用poseDirectory；对应四个R/Y/B/G-raised-body.png，现有检查、打包、预加载及构建都纳入，当前56张运行PNG。没有姿势定义的角色沿用原动作，不必补空素材。四个常规图层槽位及染色图集未改；姿势只在染完后普通贴图绘制中切换，不支持扫色中换轮廓或任意新肢体拓扑。原生源保留原躯干与脚底，仅修补双侧手臂区域。

## 短帧样板补充（2026-10-27）

poses.frames为body后缀与duration毫秒列表，当前小角怪4种姿势／7段／280ms。poses.lockedRegions声明与原身体一致的保护区，生产检查同时核对可见像素、alpha和格内余量。新增中间帧通过外层poseDirectories按部件名定位；poseDirectory继续作为默认来源。放手body不重复打包，重复姿势只加载一次。当前64张运行PNG。

CharacterMotion共享循环按elapsed采帧，染后回弹仍240ms，合群按参与角色groupDuration最大值安排；无短帧角色保持140ms。两后端仅切普通身体贴图，表情与GPU染色保持原路径，不使用每角色独立Animation定时器。胜利只播放抬手部分并保持，普通合群完整回收。这里只支持当前短身体姿势片段，不是通用动作编辑器。

## 兔耳怪小跳接入补充（DEV-0093）

兔耳怪增加takeoff-body／air-body／land-body三种四色身体，连原body组成10段360ms序列，当前运行共76PNG。外层来源为art/source/rabbit-v2/hop-runtime-v1，原五官与原静态染色图集不改。

可选frames.transform包含scale二元组和lift（256画布单位）；有此轨道的角色按整段时长播放染后动作／合群，未配置者保持原逻辑。PartyView按每格motion.bounceDuration等待，不截短兔耳怪；队伍取最大groupDuration。小角怪染后240ms／合群280ms，独眼染后240ms／合群140ms。

poses.faceAnchor和faces[body后缀]描述原固定脸层及两表情层的枢轴／位置／旋转；同组五官一起变换，无新五官PNG或染色参与。photoBody指定落地定格；兔耳怪跳完后用takeoff-body取景，小角怪保留举手峰值逻辑。定义检查约束完整轨道及首尾复位，素材检查按每帧变换检查可见身体格内余量。实际跟随、取消恢复与密集观感待用户。

DEV-0094整理：运行接口restoreRestingBody恢复原身体及脸部放置，hasBodyPoses检查是否声明身体姿势；旧lowerHands／supportsRaisedPose命名已移除。动作数据及素材不变。混排胜利中短时长角色提前复位再进入统一取景的问题已记录，尚未修复。

## 轻呼吸样板（DEV-0096）

复用原body／五官，在actor脚底枢轴上最多横向放大0.75%、纵向压缩2.5%（DEV-0099按用户反馈微调），不抬升、不换图，影子和格底不变。每格按稳定种子错开2.6～3.2秒周期，400ms渐入；PartyView共用tickAnimation，呼吸最多20Hz更新，无每角色timer。仅playing且没有染色／动作／胜利流程时待机；开始操作整盘stopIdle，两后端beginTransition也复位，动作入口优先清待机。取景／失败／关闭动作不待机，独立轻呼吸开关便于对照。reset清开始时间，不覆盖开心余留。实际可读性与手机开销待用户R22确认。

DEV-0100：为密集角色增加尺寸补偿max(1,min(1.5,55.5/size))，37像素时横向最大放大1.125%、纵向最大压缩3.75%，头顶约1.2像素；77像素仍0.75%／2.5%，避免普通角色一同加大。该目标按游戏内部坐标估算，窗口缩放后的屏幕像素需用户查看。

## 兔耳眨眼样板（DEV-0101）

可选blink.files／duration／cooldown声明独立中性闭眼层、180ms闭眼和10000ms单角色冷却。该文件由统一角色定义参与来源映射、预加载、打包、检查和构建，当前79运行PNG；眼睑不染色，所以不需要四份重复图。固定嘴／腮红照常装配，calm／happy／blink眼层互斥，闭眼时只隐藏calm眼。PartyView空闲每2～4秒最多挑一个当前候选触发，关闭轻呼吸仍保留眨眼调度；没有可眨眼物种且呼吸关闭时停空闲循环。总动作关闭、染色开始、开心／动作／取景／reset中断眨眼，重建清调度和候选，不引入每角色timer或影响Rules。当前兔耳为双眼眨眼，小角怪为左眼单眨，独眼怪为单眼闭眼。

DEV-0102：运行闭眼时长由140ms改为180ms，触发间隔与冷却不变；已有离线素材预览保留制作时140ms，仅供睁闭造型对照。
